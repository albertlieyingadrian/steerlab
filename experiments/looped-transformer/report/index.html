    A small looped transformer turns extra loops into longer reasoning only when one pass can’t do the training job

    NVIDIA’s Dory runs the same block of layers up to four times per token and lets you choose how many. We rebuilt the idea at 0.8M parameters on one question a person answers by re-reading: in a shuffled list like q=x, x=kd, kd=7, what digit does q hold?

    Summary: the short answer and the key results

    In short

    If a transformer runs the same layers again, as NVIDIA's Dory does, does it follow longer chains of reasoning?

    Only when it has to. Trained on chains of 1-8 links, which four layers can already follow in one pass, the Dory-style model (a shared two-layer block run k times, the input re-added each loop) turned extra loops into longer chains in one seed of three: 9 links at one loop, 14 at ten. The other two seeds solved 10 links at every loop count, and standard models of the same size or the same compute stopped at exactly 8. Trained on chains of up to 16 links, every seed used its loops: on a test built so that chain length gives nothing away, 10-11 links at one loop and 14-17 at four. Inside, standard models double how far they have followed the chain at every layer; the models that use their loops walk it, one link per loop, which a linear probe can watch.

    01Introduction

    Here is a question a person answers by re-reading: in a list of 48 lines such as kd=7, q=x, x=kd, shuffled, what digit does q hold? You find the line for q, which sends you to x, which sends you to kd, which says 7. A longer chain needs more passes over the list. A transformer reads the whole list at once, layer by layer, and each layer can only do so much, so a model with a fixed number of layers runs out of steps on a long enough chain. One answer is a bigger model with more layers. Another is to run the same layers again: read the paragraph once with more brain, or re-read it several times with the same brain.

    What is known. NVIDIA's Nemotron Labs Dory 1.0 4B (October 2026) takes the second route at scale: an 8-layer input block, a 20-layer recurrent block whose weights are reused on every loop with the input re-injected each time, and an 8-layer output block, with the loop count (1 to 4) chosen when the model is served. The model card reports gains from more loops on agentic and long-context benchmarks (SWE-bench Verified 50.3, 59.5 and 61.8 at 1, 2 and 4 loops) and none on knowledge (AA-Omniscience 10.0 at every loop count). The idea is older: Universal Transformers (Dehghani et al., 2018) shared one block across depth; Geiping et al. (2025) trained a 3.5B recurrent-depth model with a random number of loops per step so one checkpoint runs at any depth; Saunshi et al. (2025) showed that looping a small block matches a deep model on reasoning tasks such as k-hop induction and that such tasks need only about log k depth; and Yang et al. (2023) and Fan et al. (2024) found looped models learn algorithms and extrapolate to longer inputs.

    What is missing. A small, fully visible case where a reader can watch what the extra loops do: whether a looped model with the parameters of a 4-layer model really follows longer chains when given more loops, whether that holds past the lengths and loop counts seen in training, and what the hidden state does from one loop to the next.

    What this note does. It trains looped and standard transformers from scratch on the chain question, scores one looped checkpoint at every loop count from 1 to 16 on chains up to three times longer than any it saw, and reads the hidden state after every layer and every loop with linear probes. The plan and its pass rules were written before the counted runs.

    1. A minimal, reproducible looped transformer (prelude, shared core with the input re-added each loop, coda; random loop count in training) beside standard models of equal parameters and of equal compute.
    2. Accuracy by chain length and loop count for 3 seeds of each model, against a shortcut baseline, with two ablations (a fixed loop count in training; no re-injection).
    3. An inside view: how far each line of the list has followed its chain after each layer or loop, which shows the standard model doubling its reach every layer.
    4. A negative result with a cause: the looped recipe, applied as written, used its loops in only some seeds.

    02Setup

    The task. Each input is 48 assignments over 96 variable names, shuffled, plus a question: which digit does the query variable hold? The assignments form chains that each end in a digit; the query's chain is the one that matters, and the others are distractors (lengths 1 to 8). The hops of a question is the length of the query's chain: q=x, x=kd, kd=7 is 3 hops. Every input has exactly 48 assignments, so a longer question changes nothing but the chain. Each assignment is one input position (the embedding of its left side plus the embedding of its right side); there are no position embeddings, since the order is random, and no causal mask.

    Terms used throughout. A block is one transformer layer (attention plus MLP). Depth is the number of blocks run. A loop is one pass of the looped model's shared core; k is the number of loops. In range means hops 1-8 (the lengths trained on), near 9-16 and far 17-24. The shortcut baseline is what a model scores if it never follows the chain and picks one of the chain-ending digits in the input at random: 0.18 to 0.23 depending on hops (pure chance is 0.10). A model solves a hop count at 90% or more.

    What counts as success (fixed in the pre-registration):

    1. H1, more loops, more hops: the looped model at k = 4 beats itself at k = 1 by 0.10 or more on near chains, in all 3 seeds.
    2. H2, looping past the training count helps: its best k from 8 to 16 beats k = 6 by 0.05 or more on far chains, in 2 of 3 seeds.
    3. H3, same parameters: at k = 8 it beats standard4 by 0.10 or more on hops 9-24, in all 3 seeds.
    4. H4, same compute: at k = 4 it is within 0.05 of standard10 or above it on hops 9-24, in 2 of 3 seeds.
    5. H5, random-k training matters: looped_fixed4 trails looped by 0.10 or more on hops 1-16 at k = 1 and at k = 8, in all 3 seeds.
    6. H6, re-injection matters: without it, the best far-chain accuracy over k = 8-16 is 0.05 or more lower, in 2 of 3 seeds.
    7. I1 and I2, inside: in standard4, the number of links each assignment has resolved reaches at least 1, 2, 4, 8 after layers 1-4 (all seeds); in looped, it is larger after loop 4 than after loop 1 (all seeds).

    03How the study was run

    1. Pilots on seed 0 (five rounds, listed in the executions log): they set the task size, showed that the first looped design did not train, and fixed the recipe. None is analysed here.
    2. Write and commit the pre-registration, including what the last pilot had shown (12-hop accuracy at k = 1, 4 and 8 for one seed), so the reader can discount the hypotheses it informed.
    3. Train the 15 counted models (5 models × seeds 1-3), 20,000 steps of fresh random examples each, on Modal L4 GPUs, three at a time; 12 to 27 minutes per model.
    4. Score every model on the same fixed test set: 500 questions at each hop count 1-24 (12,000 questions), looped models at k = 1, 2, 3, 4, 5, 6, 8, 10, 12 and 16.
    5. Amendment 1, written after reading the three looped runs and before the others finished: an exploratory follow-up that trains on hops up to 16 (9 more models).
    6. Probe 12 models on Modal: linear probes fitted on 3,000 fresh questions and scored on 3,000 others, after every layer and every loop up to 16.
    7. Analyse with analyse.py, which scores every rule exactly as written; figures, the interactive figure's data and the cover are drawn from its output.

    Before the pre-registration, the pilots changed three things. The first looped design re-injected the input through a new linear layer on every loop (Geiping et al.'s form) and never got past the shortcut, at any learning rate tried; re-adding the input as Dory does trained, and it also makes the parameter counts of looped and standard4 identical. A 32-assignment version of the task left so few distractors at 24 hops that guessing scored about 0.5, so the input grew to 48. And on the larger task every model stalled at 2 hops without a curriculum, so all models now start at 1-2 hops and add one whenever they reach 95% on what they have.

    Conditions: PyTorch 2.6 on Modal L4 GPUs (one per model), at most three at once; fresh examples every step, never repeated; the test set is generated from a fixed seed and shared by every model. Spend: $16.84 of Modal (billing report): $12.44 for the counted runs, the follow-up, the probes and the control set (about 10.3 A10G GPU-hours), and $4.40 for the pilots, $2.11 of it lost when the first workspace was disabled mid-run. No API models.

    Try the 10-hop question with the k = 4 model: the orange in its top row moves down the chain as the loops go on (per question the probe is noisier than in Figure 3B), and its answer is wrong for five loops and right from loop 6 (probability 1.00), then fades again (0.76 at loop 16). The standard model's bottom row fills in jumps (over all test questions, the last 1, 2, 3, 5 and 9 links after layers 0-4), the pattern of pointer doubling.

    4.2 Standard models stop exactly at the longest chain they trained on

    Both standard models solve every question of 1 to 8 hops and almost none longer: the longest chain solved is 8 hops in all three seeds of the 4-layer model and 8, 9 and 8 for the 10-layer model, which has 2.4 times the parameters. On 9-16 hops they score 0.165 and 0.193, at or below the shortcut baseline (0.198). Ten layers bought nothing past the training range; Figure 1A shows both curves dropping off the same cliff.

    4.3 The Dory-style model answered longer chains with more loops in one seed of three

    H1 failed: from 1 to 4 loops, accuracy on 9-16 hops rose by +0.10, +0.38 and +0.06 in seeds 1, 2 and 3 (bar: +0.10 in all three). Seed 2 used its loops: the longest chain it solves grows from 9 hops at k = 1 to 12 at k = 4, 13 at k = 6 and 14 at k = 10-16, past both the training length and the training loop count. Seeds 1 and 3 solve 10 hops at k = 1 and stay at 10 however many loops they get. Figure 1 B-D shows the difference: in seed 2 each loop count draws its own cliff further right; in seeds 1 and 3 the cliffs pile up.

    The looped model still beats the standard model of the same parameters and depth: at k = 1 it runs 4 blocks, like standard4, and solves 9-10 hops instead of 8. But H3 failed too: at k = 8 its lead over standard4 on hops 9-24 was +0.07, +0.40 and +0.13 (bar: +0.10 in every seed). H4 passed: at k = 4 it matched or beat the 10-layer model, which has the same compute and 2.4 times the parameters, by +0.17, +0.28 and +0.02.

    Why would a model trained with random loop counts not use its loops? Training draws k from 1 to 6, so the one-loop path must answer every training question by itself, and 4 blocks are enough for 8 hops (the standard model proves it). Nothing in the loss rewards spreading the work over loops; in two seeds the model put all of it in the first one. Section 4.7 tests this reading.

    4.4 No model reaches the far chains

    On 17-24 hops every model scored between 0.11 and 0.25 at every loop count, around the shortcut baseline of 0.22. H2 failed: looping past the training maximum (k = 8-16 against k = 6) changed far-chain accuracy by +0.03, +0.05 and −0.01. Even seed 2, the best extrapolator, solves 14 hops at most. Several models score below the shortcut at long chains (seed 1 at k = 1: 0.08), so they are not guessing among chain ends: they answer with a confident wrong digit, most likely the end of a chain they reached partway.

    4.5 Both ablations used their loops more than the Dory-style model did

    Trained always at k = 4, the looped model is broken at fewer loops (it solves 5 hops at k = 1, so 70% of training-range questions right) and walks further with every extra loop: 5, 6, 7, 8, 9 and 10 hops at k = 1-6 in seed 1 (seeds 2 and 3 alike), 9-11 at k = 8, then back down to 7-8 at k = 16. At k = 8, a loop count it never trained at, it solves 9-11 hops in all three seeds. So H5, which expected the fixed model to trail at k = 8, failed: its gap to the random-k model on hops 1-16 was −0.02, +0.13 and −0.06 at k = 8. At k = 1 the random-k model was ahead by +0.25, +0.24 and +0.22, which is what random-k training buys: a checkpoint that still works when stopped early.

    Without re-adding the input, the looped model solved 8 hops at k = 1 and 10-12 at k = 4-8 in every seed; on 9-16 hops at k = 8 it scored 0.671 against 0.559 with re-injection. H6, which expected the opposite, failed: −0.055, +0.004 and −0.040. A guess at why, not tested: with the input re-added at every loop, the core always sees the original list and can redo the whole job from scratch in one pass; without it, each loop can only build on the last loop's state, which pushes the work to spread over loops. Both ablations are 3 seeds; the reversal is consistent in direction for fixed k at small k and for re-injection in 2 of 3 seeds.

    4.6 Inside, standard models double their reach each layer; models that use their loops walk one link per loop

    In the 4-layer model, the longest chain whose answer a probe can read at the question's position is 0, 0, 2, 4 and 8 hops after the embedding and layers 1-4, the same in all three seeds: it doubles every layer. In the model trained at k = 4, the question's state names the variable i and i + 1 hops down its chain after loop i, and forgets the earlier ones (Figure 3B): it walks. The pointer probe at the 48 lines tells the same story for the standard model: after layer 2 a line knows the variable 2 links on, after layer 3 the one 4 links on (reach 1, 1, 2, 4, 4), but not the one 3 links on, which is the signature of pointer doubling (each line reads the line its pointer names and jumps twice as far; see the schematic in Figure 4).

    The models that use their loops all walk. The no-reinjection model's frontier climbs 3, 4, 6, 6, 8, 9, 9, 10, 11 over loops 1-9 (seed 1), and seed 2 of the Dory-style model climbs 5, 7, 8, 9, 9, 10, 11, 11, 12, 13. Seeds 1 and 3 of the Dory-style model jump to 6 after one loop and 8-10 after two, then stay: they did the work in the first loops, by a faster route than walking, and the rest of the loops have nothing left to do.

    The two pre-registered checks used the digit probe at the 48 lines, and both failed narrowly. I1: the 4-layer model's digit frontier was 1, 2, 3, 5, 9 in seeds 1 and 2 (above 1, 2, 4, 8) and 1, 2, 3, 5, 5 in seed 3. I2: the Dory-style model's frontier rose from loop 1 to loop 4 in seeds 1 and 2 (7 to 8; 6 to 10) and stayed at 7 in seed 3. The digit probe is also blind where the question's probe is not: the fixed-k model answers 10-hop questions while its lines show at most 2-6 resolved links, because that model does its work at the question's position, not at every line.

    The state does not settle. The mean relative change of the hidden state between loops falls as 0.44, 0.31, 0.24, 0.19 … from loop 2 on, the same at every hop count and in every looped model: about 1/i, which is what a state whose length grows with each re-added input would show. It is not the fixed-point convergence Geiping et al. report for their model, and it does not mark when a question is finished; a halting rule would need a different signal.

    4.7 When training needs more than one pass, every seed uses its loops (exploratory, with a shortcut found on the way)

    Amendment 1, written after the first three looped runs, trained the same three models on chains up to 16 hops, so that 4 blocks could no longer answer every training question. On the standard test the result looked too good: the looped models scored 0.84-1.00 on 17-24 hops, and so did the 4-layer standard model in two seeds, although 4 blocks cannot follow 24 links by doubling. The test allowed a shortcut: its distractor chains are at most 8 long, so any chain longer than 8 is the question's, and a model can answer by elimination (the chain end no short chain leads to) without following anything. Amendment 2, written before looking at any control result, added a control set in which one distractor chain is exactly as long as the question's.

    On the control set, the main models were unaffected (within 0.03 of their standard-test accuracy on 9-16 hops in every seed), so what they solved in sections 4.2-4.5 was chain following. The models trained to 16 hops were not: the 4-layer and 10-layer models lost 0.19-0.31 on 9-16 hops in two seeds each. The looped model lost 0.02-0.09, and it used its loops in all three seeds: the longest chain solved went from 10, 11 and 10 hops at k = 1 to 14, 17 and 14 at k = 4 (the 4-layer standard model with the same training: 11, 10, 10). On 9-16 hops its control accuracy rose from 0.72, 0.87 and 0.68 at k = 1 to 0.91, 0.99 and 0.95 at k = 4, so the expectation E1a passes when scored on the control set (it failed on the standard test, where k = 1 already scored 0.95-1.00 by elimination). On 17-24 hops, past even this training range, no model got far: 0.56-0.67 for the looped model against a control shortcut baseline of 0.35 and 0.49-0.55 for the 4-layer model; E1b and E1c failed on both test sets.

    So the reading in 4.3 survives its test: once the one-loop path cannot do the training job alone, the looped model spreads the work over loops in every seed, and extra loops help on chains longer than one pass can follow. The detour also carries a lesson for any length-generalisation claim: a test whose distractors are all short rewards a model for spotting the long chain, not for following it.

    05Implications for AI safety

    A looped model reasons in its hidden state, not in tokens, so the reasoning cannot be read off a chain of thought. In this toy, at least, it can be read off the hidden state: a linear probe saw where the question's state was on its chain after each loop, and the walk it showed matched the answers. That is a reason for optimism about monitoring latent reasoning: each loop is a natural place to read.

    The second lesson is about claims of elastic compute. The same recipe, with the same data and hyperparameters, produced a checkpoint that used extra loops and two that did not, and the difference was invisible on the training range (all three were perfect on 1-8 hops at every k). A user who turns up the loop count expecting more careful reasoning may get the same answer at more cost.

    Recommendation: when a model offers a loop or depth knob, test what the knob buys on held-out questions longer than training, checkpoint by checkpoint, and read the hidden state at each loop; do not assume more loops means more reasoning.

    06What this does not show

    • One toy task, tiny models. 0.8M-parameter encoders on shuffled assignments, not language models. Dory's gains are on agentic and long-context benchmarks; nothing here tests those, or Dory itself.
    • Three seeds. The headline is a split between seeds (1 of 3 used its loops). Three seeds can show that the outcome varies; they cannot estimate how often each outcome happens.
    • The recipe was tuned in pilots. The first looped design (Geiping et al.'s concatenate-and-project injection) never trained here; the curriculum was added because no model trained without it at 48 lines. A different recipe, a longer run or a different curriculum might change which seeds use their loops.
    • Linear probes. A probe that cannot read something does not show the model lacks it (the digit probe missed the fixed-k model's progress entirely). The pre-registered inside checks used that probe; the clearer pictures come from the question's position, which was listed as descriptive.
    • A pilot informed three hypotheses. The last pilot showed 12-hop accuracy at three loop counts for one seed and the 4-layer model's doubling pattern before H1, H3 and I1 were written; all three failed anyway.
    • The explanations are untested. "The one-loop path solves training, so loops go idle" and "re-injection lets each loop redo the job" fit the results but were not tested by an intervention; the follow-up in 4.7 tests the first only partly.
    • Hardware. Models trained on Modal A10G GPUs (the L4s requested were not available); results are not bitwise reproducible across GPUs.

    07Reproduce it

    Everything is in experiments/looped-transformer/. bash experiments/looped-transformer/reproduce.sh --dry-run prints every command; without --dry-run it retrains all 24 models and reruns the probes on Modal (about 10 A10G GPU-hours, about $12), then rebuilds every number, figure and the interactive figure on a laptop in under a minute:

    modal run experiments/looped-transformer/modal_train.py --models looped,standard4,standard10,looped_fixed4,looped_noinject --seeds 1,2,3
modal run experiments/looped-transformer/modal_train.py --models looped,standard4,standard10 --seeds 1,2,3 --extra "--max-hops 16 --tag _h16"
modal run experiments/looped-transformer/modal_train.py --task inside --runs looped_s1,...
python experiments/looped-transformer/analyse.py      # every number, results/summary.json
python experiments/looped-transformer/make_figures.py
python experiments/looped-transformer/make_demo.py

    A single model trains on a laptop too (python experiments/looped-transformer/train.py --model looped --seed 1; about 15 minutes on an Apple M-series GPU for the 4-layer model).

    08What’s next

    • Make the walk the only option. Train with a loss at every loop (each loop must improve on the last), or with k drawn from a range that starts above 1, and count how many of 10 seeds use their loops.
    • A halting signal. The state's relative change did not mark when a question was done; the probe for the question's position did. Test whether a probe-based stopping rule saves loops without losing accuracy.
    • A causal test of the walk. Patch the question's state from one loop into another question and check that the model continues from the patched variable.
    • Language. Repeat the probe reading on Dory itself, on multi-hop questions, loop by loop.
    • Follow-up (Episode 2): a looped transformer built from scratch on a version of this task where one pass cannot reach the training length uses its loops in every seed (9 links at 16 loops after training on 6), shows the digit moving back one statement per loop, and tests per-loop lenses, patching across loops and a shared sparse autoencoder.

    09Questions and answers

    What is a looped transformer?

    A transformer that runs one block of layers several times in a row with the same weights, instead of stacking many different layers. NVIDIA's Dory 1.0 4B runs an 8-layer input block, then a 20-layer block 1 to 4 times with the input added back each time, then an 8-layer output block; the user picks the number of loops when serving it. More loops cost more compute but no extra memory for weights.

    Does running more loops make a looped model reason further?

    Sometimes. In a 0.8M-parameter Dory-style model trained to follow chains of 1 to 8 assignments, one of three seeds solved chains of 9 hops with 1 loop and 14 hops with 10 loops; the other two solved 10 hops at every loop count. All three were perfect on the training lengths at every loop count, so the difference only showed on longer questions.

    Why would a looped model ignore its extra loops?

    Because training let it. With the loop count drawn from 1 to 6 at each step, the one-loop path has to answer every training question on its own, and 4 blocks are enough for 8 hops. Two seeds put all the work in the first loop. A model trained always at 4 loops could not do that: it walked one link per loop, and then kept walking when given 8 loops at test time.

    Does a deeper standard transformer follow longer chains?

    Not past what it trained on. A 4-layer and a 10-layer model both solved exactly 1-8 hops and fell to guessing at 9. The looped model with the parameters of the 4-layer model solved 9-14 hops, depending on seed and loops.

    What does the hidden state do from one loop to the next?

    In models that use their loops, a linear probe at the question's position names the variable one more hop down the chain after each loop: the model walks the chain. Standard models instead double their reach each layer (2, 4, 8 hops), a pointer-doubling algorithm. The state's overall change between loops falls like 1/i in every looped model and never settles to a fixed point.

    Does re-adding the input at every loop help?

    Not here. Without it, the looped model used its loops in all three seeds (10-12 hops at 4-8 loops) and scored 0.67 on 9-16 hops against 0.56 with it. Re-injection is meant to keep a long loop from drifting away from the question; on this task the drift was not the problem.
