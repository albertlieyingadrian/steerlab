    A looped transformer built from scratch follows one more link per loop, past anything it trained on

    A looped transformer runs the same block of layers again and again, so it can think longer without storing more weights. We built one from a blank file, trained it on a laptop CPU in five minutes, and then opened it up loop by loop to see how it uses the extra passes and which interpretability tools can still read it.

    Summary: the short answer and the key results

    In short

    How does a looped transformer work, and what can you still read inside one?

    It splits the layer stack into a prelude run once, a core whose weights are reused K times, and a coda run once, and it re-adds the prelude's output before every loop. Trained with a random K per batch on chains of up to 6 links, our 157,578-parameter model solves about one more link for every extra loop: 9 links at K = 16 in all three seeds, three more than it ever saw. Standard models with the same weights (3-4 links) or the same compute (4-6) don't get past the training length. Inside, the answer digit flows back along the chain one statement per loop. One lens (even the plain logit lens) reads every loop of this model; a variant whose passes restart from the input needs a lens fitted to it, and there a Jacobian lens reads almost nothing between loops.

    101: what is a looped transformer?

    A standard transformer is an assembly line of different workers, each seen once: block 1, block 2, block 3. A looped transformer hires one worker for the middle of the line and sends the work past them K times. Same wages (parameters), more hours (compute). Recent open models do this at scale: Inkling 2 Mini runs its middle 12 of 24 layers three times (model blog), NVIDIA's Dory runs a 20-layer block 1-4 times (model card), and Huginn runs a 4-layer core 4 to 64 times (arXiv 2502.05171). Because K is just an argument of the forward pass, one trained model can be asked to think for 1 loop or for 16.

    01Introduction

    Give a person 24 shuffled lines like k=d, q=k, d=7 and ask what q holds. They follow the links, one lookup per link. A transformer with three blocks gets three rounds of lookups and then must answer. Our looped model with the same three blocks of weights solved chains of 9 links when allowed 16 loops, after only ever training on 6, and its own inner states show it doing one link per loop.

    What is known. Looping a shared block is an old idea (Universal Transformers) now shipped at scale: Huginn's prelude, recurrent core and coda (arXiv 2502.05171), Ouro's whole-stack loops with a learned exit (arXiv 2510.25741), Dory's re-added input, Inkling 2 Mini's gated messages between passes. Small studies show looped blocks learning iterative algorithms (arXiv 2311.12424) and matching deeper models on reasoning (arXiv 2502.17416). On the inside, a 2026 preprint applying the Jacobian lens to Ouro and Huginn (arXiv 2609.01924) found that Ouro rebuilds its content every loop, so a lens and any edit must be made per loop, while Huginn carries content forward and its reads and edits act within about two recurrences.

    What is missing. A version small enough to build from an empty file and train on a laptop, where every one of those ideas (re-injection, random K, same-weights and same-compute baselines, per-loop lenses, patching across loops) can be run and checked in minutes, with controls.

    What this note does. It builds a character-level GPT the nanoGPT way, turns it into a looped model with a twenty-line change, trains it beside two standard models and two looped variants on a chain-following task, and then reads it with six tools, loop by loop. Contributions:

    1. A from-scratch looped transformer that turns extra loops into longer chains, past the training length, in every seed, against fair baselines.
    2. A mechanism you can see: the digit moves back along the chain one statement per loop.
    3. A small, controlled version of the per-loop lens result: one lens suffices when loops carry their state forward; restart-style passes break the Jacobian lens between loops.
    4. Two negative results: a plain "stop when the answer stops changing" exit fails on long chains, and on this toy a shared sparse autoencoder adds sharpness, not discovery.

    02Setup

    The task. A puzzle is 24 statements over 48 variable names, shuffled, plus a question q?. The statements form chains that each end in a digit. The question's chain has h links (hops); a twin chain has the same length and ends in a different digit; the rest are distractor chains of 1-4 statements. Each statement is one input position, embedded as lhs[a] + rhs[b]; there are no position embeddings and no causal mask. The twin exists because our earlier note found models answering long chains by elimination ("the longest chain is the question's") without following anything; with a twin, that guess is right half the time, so at 12 links (only the two chains are left) 0.5 is the floor.

    Terms used throughout. A block is one transformer layer (attention plus MLP). A loop is one pass through the looped model's shared core; K is the number of loops at test time. Longest chain solved is the longest length with at least 90% right on it and on every shorter length. Re-adding the input means s = core(s + e), where e is the prelude's output and s starts at zero.

    The whole change from a standard GPT is the forward pass:

    e = prelude(embed(idx))          # once
s = zeros_like(e)
for _ in range(k):               # the same weights every time
    s = core(s + e)              # re-add the input before every loop
logits = head(ln_f(coda(s)))     # once

    What counts as success, decided before the counted runs:

    1. More loops solve longer chains in every seed, including lengths never seen in training.
    2. The looped model beats the same-weights model, and at least matches the same-compute model, on chains of 7-12 links.
    3. Each interpretability claim beats its control: shuffled labels and an untrained model for probes; a random vector of the same size for patching; random directions for the sparse autoencoder.

    03How the study was run

    1. Build and check the GPT: tokenizer, attention with a mask test (editing the last position moves earlier outputs by exactly 0.0), the block, and the training loop; a 4-block, 212,545-parameter model reaches validation loss 1.72 on tinyshakespeare in 2,000 steps (29 seconds).
    2. Loop it and check that the looped and 3-block models have identical parameter counts and that the shared block's gradient equals the sum of the gradients of K unrolled copies.
    3. One pilot on seed 0 (three models, 4,000 steps, with the loop's starting state set to e instead of zero) to check that the 3-block model could not reach 6 links while the looped one could. We then switched the starting state to zero, the form of the looped in-context-learning code. The pilot's numbers are not reported.
    4. Train the 15 counted models (5 models × seeds 0-2), 4,000 steps of 128 fresh puzzles, AdamW at 2e-3 with warm-up and cosine decay, a curriculum that starts at 1-2 links and adds one whenever the last 50 batches were 90% right, up to 6.
    5. Score every model on one fixed test set: 500 puzzles at each length 1-12; looped models at K = 1, 2, 3, 4, 6, 8, 12, 16.
    6. Read the looped models at K = 8 with the logit and coda lenses, tuned and Jacobian lenses, probes, patching, loop ablation, convergence and a shared sparse autoencoder, each on fresh puzzles with its own seed.
    7. Add three readouts after a first look (marked below): probes at the chain's statements, 8-link chains in the loop ablation, and a random-direction track for the sparse autoencoder.

    04Results

    4.1 Every extra loop buys about one more link, past the training length

    Figure 1 is the whole result in one picture. With K loops, seed 0's model solves chains of K + 1 links: 2 at K = 1, 3 at K = 2, 4 at K = 3, 5 at K = 4, 7 at K = 6. The rule keeps going where training stopped: 8 links at K = 8 (0.90) and 9 at K = 16 (0.91), with 6 the longest chain it ever saw. Seeds 1 and 2 follow the same rule from a one-link head start (3 links at K = 1) and also reach 9 at K = 16 (Figure 2). Gains stop around 9-10 links: at 10 links K = 16 reaches 0.60, 0.79 and 0.66.

    At K = 1 the looped model is a 3-block model and does no better than one (2-3 links against 3-4): all its advantage is in the loops. At K = 8 it runs as many blocks as the 10-block model with under a third of its weights and solves 2-3 more links. The 10-block model learned the training range in one seed (6 links, seed 1) but on 7 links scored 0.25-0.58: no standard model reached past 6. A caveat on fairness: every model got the same 4,000 steps, and the deep standard model trains more slowly (seed 0 reached only 0.73 on 5 links); a longer schedule could lift it inside the training range, though nothing in its grids points past it.

    4.4 Inside, the digit flows back along the chain one statement per loop

    The logit lens at the question shows the answer arriving all at once: for 6-link chains it reads 0.13-0.19 after loops 0-4 and 1.00 after loop 5 (seed 0), so the work must happen somewhere else. Probes on the chain's own statements find it (Figure 3). At the statement d links from the chain's end, a linear probe reads the chain's digit perfectly from loop d − 1 on and at chance before: the statement next to the digit knows it from the prelude, the one before it after loop 1, and so on. The digit flows backward along every chain at once, one statement per loop, and the question reads it the loop after it reaches the chain's first statement (answer probe 0.23 at loop 4, 1.00 at loop 5). The question itself does not walk forward: the name 3-5 links along is never readable there (at most 0.05, chance 0.02). Seed 2 shows the same staircase; seed 1 is one step ahead, which is its one-link head start in Figure 2. The coda adds one link of its own, which gives "K loops solve K + 1 links".

    4.5 One lens reads every loop when loops carry their state forward, and not when passes restart

    The logit lens applies the model's final LayerNorm and head to the state after loop i. A tuned lens (arXiv 2303.08112) first applies a small learned map, fitted so the decoded answer matches the model's own; we fit one per loop and one shared by every loop. The Jacobian lens fits nothing: it pushes the state through the rest of the model with the average Jacobian from loop i to the end, one matrix per loop, or one matrix averaged over the loops.

    For the model that re-adds its input, all five agree within 0.07 from loop 1 on, in every seed (Figure 4, left): the state after loop 3 is in the same format as the state after loop 8, so the free logit lens is as good as anything fitted. The plain loop behaves the same. The Inkling-style model, whose every pass restarts from the input, is different (Figure 4, right, seed 1): the logit lens reads 0.42-0.69 at loop 8, the per-loop Jacobian lens reads 0.04-0.19 at loops 1-7 and only works after the last loop, and a tuned lens recovers the content (0.78-0.99 at loop 8; one shared tuned lens does nearly as well, 0.75-0.96). A straight-line transport from a mid-run state to the end carries almost nothing across pass boundaries, the small-scale version of what the Jacobian-lens preprint found for Ouro. One wrinkle: the averaged Jacobian lens beats the per-loop one here, because the average is dominated by the last loop's matrix, the only one that works.

    4.6 Edits made late stick; edits made early wash out

    A corrupted run keeps all 24 statements and changes only the question, to the twin chain's first name. Copying the clean run's state in right after loop i (Figure 5): after loop 0, the prelude's output, the clean answer returns every time, since that output is the input re-added on every loop. After loop 1 it returns in only 2-5% of runs: on loop 2 the corrupted input is added back and wins. After loop 3, once the answer has reached the question in 4-link chains, it returns in 96-99%. A random vector of the same size returns it in at most 8% (0-2% after loop 0). The state grows by about the same amount each loop while the re-added input stays the same size, so an edit made early is outvoted by the input and one made late is not: a toy version of the preprint's finding that edits to Huginn act within a window of recurrences.

    4.7 Every loop does the same job, and the state never settles

    Skipping one loop out of eight leaves 6-link chains at 1.00 (they need 5) and costs 8-link chains the same whichever loop is skipped: 0.91 → 0.75, 0.97 → 0.95 and 0.98 → 0.93 (seeds 0-2). The loops are interchangeable steps. The question's state never reaches a fixed point: its length grows by about 28 per loop (22, 42, 85, 196 and 417 after loops 1, 2, 4, 8 and 16), so the relative change falls as 1/i (0.78 → 0.07) without stopping, the same curve as our earlier note. The decoded answer settles, though: it never flips after loop 6.

    4.8 A sparse autoencoder shared by every loop sharpens the picture but finds nothing new

    Because the loops reuse the same weights, one dictionary can serve every loop, so a latent at loop 3 is the same latent at loop 7. A TopK autoencoder (256 latents, 8 active) trained on the question's state after loops 1-8 (each loop scaled to the same average length) rebuilds it well (unexplained variance 0.04-0.06) and has one latent per answer digit (selectivity 0.86-0.99). Followed back through the loops, the true digit's latent switches on at the loop the digit reaches the question and stays on (Figure 6). The boring explanation holds partly: random directions separate the digits at the last loop nearly as well (0.64-0.99), and tracked the same way they show the same staircase, blurred (5-link chains after loop 4: 0.46 / 0.78 / 0.08 against the autoencoder's 0.93 / 1.00 / 0.98). On this toy the autoencoder adds a crisp "the answer has arrived" signal in one shared dictionary; the probe and logit lens had already found the answer.

    4.9 Negative result: "stop when the answer stops changing" quits too early

    Running every loop up to 16 and stopping at the first loop whose answer equals the previous loop's uses 2 loops on 1-2-link chains, but about 3 on every longer chain, so 8-link accuracy falls from 0.99 to 0.37, 0.42 and 0.34 (seeds 0-2). Before the digit arrives the coda's guess is often wrong but stable from one loop to the next. Section 4.4 suggests a better signal (stop when a probe at the question reads a digit); Ouro trains an exit gate for this reason.

    Why did every seed use its loops here and only one seed in the earlier note? There, chains up to 8 links were within reach of four blocks in one pass, so the model had no need to loop.     06Implications for AI safety

    Looped models move reasoning from visible tokens into repeated passes over a hidden state. That makes two things matter for monitoring. First, which lens you can trust depends on how the loops pass state: a model that carries its state forward can be read loop by loop with one cheap lens, while a model whose passes restart and exchange messages (as Inkling 2 Mini's do) needs lenses fitted to it, and a Jacobian lens can read nearly nothing between passes. Second, edits and monitors placed early in the loop are overwritten by the re-added input, so an intervention has to be applied late, or on every remaining loop. Before relying on a lens or a steering edit in a looped model, check it per loop against a fitted baseline on that model's own loop type.

    07What this does not show

    • Scale. 157,578 parameters on a synthetic task. Real looped models have many layers per loop, positions, causal masks and language; the lens split we see may look different there.
    • Seeds. Three per model. The message model's one failed seed in three shows how much a single run can mislead.
    • Training budget. Every model got 4,000 steps. The 10-block standard model may be under-trained inside the training range.
    • Readouts at K = 8 only, on the question and the question's chain; we did not probe distractor chains, other loop counts, or the coda's internals.
    • Three readouts were added after a first look (statement probes, 8-link ablation, random-direction tracking); they are labelled where they appear.
    • The message model is a one-gate simplification of Inkling 2 Mini's per-layer, per-input messages, and our Jacobian lens is a single-position version (question to question) of the preprint's.

    The training and analysis program is a from-scratch course ("build your own looped transformer", one command per stage, tests per stage): code release coming soon. Every number in this note is in results/seed0/, seed1/ and seed2/ (for example compare_s0.json), and make_figures.py redraws every figure from it and prints the numbers it plots:

    .venv/bin/python experiments/looped-transformer-from-scratch/make_figures.py
experiments/looped-transformer-from-scratch/reproduce.sh --dry-run

    The core of the method fits in a few lines. The looped forward pass is in section 2; random K is one line of the training loop, k = rng.integers(1, 9) per batch; and the Jacobian lens for loop i is one backward pass per output number:

    for j in range(d):                                  # d = 64 numbers in the final state
    grads = torch.autograd.grad(final[:, j].sum(), states, retain_graph=True)
    for i, g in enumerate(grads):                   # states[i]: after loop i
        J[i][j] = g[:, question].mean(0)            # average over puzzles
readout_i = head(ln_f(states[i][:, question] @ J[i].T))

    10Questions and answers

    How does a looped transformer work?

    It runs a prelude once, then the same core block (or blocks) K times, re-adding the prelude's output before each pass (or, Inkling-style, restarting from it with a message from the last pass), then a coda once. Trained with a random K, the same weights can be run at any K; more loops cost compute, not memory for weights.

    Does a looped model beat a bigger standard model?

    On this task, yes: at K = 8 it runs as many blocks as a 10-block model with under a third of the weights, and solves 7-8 links against 4-6. With the same weights and no extra loops (K = 1) it is no better than a 3-block model.

    Does the Jacobian lens work on looped models?

    On loops that carry their state forward, yes, and so does the plain logit lens. On passes that restart from the input it reads almost nothing between loops (0.04-0.19 here). Use a tuned lens fitted to the model, probes at the right positions, and patching per loop; check each against a control.

    Should I train a sparse autoencoder per loop or one for all loops?

    One for all loops, if the weights are shared: a latent then means the same thing at every loop, so you can follow it. On this toy it gave a sharp on-off signal for when the answer arrives, but random directions found a blurred version of the same thing, so check it against them.

    Does a looped model converge to a fixed point?

    Not this one: with the input re-added, its state grows by about the same amount every loop forever. The answer stops changing after enough loops, which is a better stopping signal than the state, though "answer unchanged since last loop" stops too early on long chains.
